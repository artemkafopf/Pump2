# Свод: идентичность скважины и фильтр не-нефтяных стволов — задача для сборщика Свода

Дата: **2026-07-21**. Адресат — процесс, который СОБИРАЕТ «Отказы свод с анализом.xlsx»
из ПДК / Big / телеметрии / техрежима. Проблема найдена ниже по потоку (в survival-модели,
которая Свод потребляет), но чинить её надо в сборке. Документ самодостаточный.

---

## 1. Что такое Свод и кто на нём стоит

Свод — канонический реестр ПРОБЕГОВ УЭЦН: одна строка = одна «жизнь насоса»
(монтаж → остановка), с колонками `Скв.`, `Дата монтажа`, `Дата остановки`,
`Наработка (сут)`, `Причина остановки`, `Отказавший узел`, `Кислый/Некислый`,
`Принадлежность` (подрядчик). На нём стоит вся survival-аналитика отказов ЭЦН (Вейбулл по
стратам, прогноз ремонтов, интенсивность отказов). Ошибка идентичности скважины в Своде
превращается в фантомный насос в прогнозе.

## 2. Что мы обнаружили (подтверждено данными)

**Небурильные стволы под тем же номером затекают в популяцию отказов ЭЦН.** Конкретный
случай — VT_2704:

| well_key (Big) | монтаж | подъём | Назначение | is_esp_strict |
|---|---|---|---|---|
| `vt_2704` | 2023-02-13 | **никогда** | Мех. добыча | True |
| `vt_2704рс` | 2023-02-13 | 2023-04-28 | Мех. добыча | True |
| `vt_2704рс` | 2023-05-04 | 2023-09-26 | Мех. добыча | True |
| `vt_2704рс` | 2023-11-06 | 2024-05-06 | Мех. добыча | True |
| `vt_2704рс` | 2024-05-08 | **никогда** | **Нагнетательная** | False |

`рс` = **рассольная** скважина — отдельный физический ствол, НЕ нефтяной. По проектной
документации 2704 нефтяной скважиной не была вообще; её последнее состояние —
нагнетательная. Но нормализация кода `norm_well` регуляркой `^([A-ZА-Я]+_\d+)` **срезает
суффикс `рс`**, поэтому `vt_2704рс` схлопывается в `VT_2704` и сливается с открытой
строкой `vt_2704`. Результат — фантомный «живой нефтяной насос возрастом 1234 сут»,
которого физически нет.

**Масштаб (Big):**
* 228 строк с суффиксом `рс`, 89 уникальных рассольных стволов;
* назначения: Нагнетательная 28, Пьезометр 19, водозаборная (ВД+НД) 25, консервация 20,
  Мех. добыча 119, прочее — то есть в основном это НЕ нефтедобыча;
* при этом **117 из 228 помечены `is_esp_strict = True`** и потому проходят в популяцию;
* **58 нормализованных `рс`-кодов реально доходят до популяции**, давая **16 фантомных
  «живых» (открытых) пробегов** (VT_2704 1234 сут, YAW_5103 1025, YAW_223 1010, …);
* **5 кодов прямо КОЛЛИДИРУЮТ** с нефтяной скважиной того же номера: VT_2704, VT_5607,
  YAW_5002, YAW_5601, YAW_5606. Именно эти пять сливают две разные скважины в одну.

`YAW_`/`BTW_` — это водяные/рассольные ПРЕФИКСЫ полей; они не мапятся на нефтяное
месторождение и в пофилдовый прогноз не попадают (но засоряют глобальный пул).
Опасны именно коллизии по нефтяному префиксу (`VT_`, `YA_`, …).

## 3. Правильная обработка (что сборщик обязан делать)

1. **Сохранять суффикс ствола в идентификаторе.** Ключ скважины = префикс + номер +
   суффикс ствола (`рс`, `РС`, боковые стволы, `рс2` и т.п.). Рассольный `2704рс` и
   нефтяной `2704` — РАЗНЫЕ ключи, они не имеют права схлопываться. Нормализацию делать
   так, чтобы суффикс сохранялся, а различались лишь регистр/пробелы/латиница-кириллица.
2. **Фильтровать не-нефтяные стволы из Свода (или помечать колонкой типа).** Исключать по
   назначению: `Нагнетательная`, `Пьезометр`, `водозаборная ВД/НД`, `консервация`,
   `ликвидирована`, `Техн. операции`, а также по суффиксу `рс`. Свод отказов ЭЦН — это
   реестр НЕФТЕДОБЫВАЮЩИХ пробегов; рассольные/нагнетательные/водозаборные стволы туда не
   входят. Если по каким-то из них ЭЦН действительно работает на мех.добыче нефти —
   решение принимать по НАЗНАЧЕНИЮ ствола, а не по наличию насоса.
3. **`is_esp_strict` не должен ставиться на не-нефтяные стволы.** Сейчас он True на 117
   рассольных строках — это и есть корень утечки. Признак «строгий ЭЦН» обязан включать
   проверку назначения ствола, а не только тип оборудования.
4. **Дедуп источников — по (ключ_с_суффиксом, дата_монтажа ± допуск), внутри КАЖДОГО
   источника тоже.** Отдельный дефект: одна и та же скважина приходит из Big и открытой,
   и закрытой строкой под тем же монтажом (VT_2704: `vt_2704` открытая + `vt_2704рс`
   закрытые). Если ключи различать по суффиксу, эта коллизия исчезает сама; но дедуп
   внутри источника всё равно нужен для страховки.

## 4. Тесты, которые обязательно включить

* **T1 — суффикс не срезается**: `key('Vt_2704рс') != key('Vt_2704')`; то же для верхнего
  регистра, латиницы, пробела (`'VT_2704 РС'`).
* **T2 — VT_2704 не в нефтяной популяции**: после сборки среди нефтяных пробегов Vt нет
  ни одной строки с ключом рассольного 2704; конкретно — нет открытого пробега
  `монтаж 2023-02-13, подъём отсутствует` под кодом VT_2704.
* **T3 — ни одного `рс`-ствола в strict-ESP нефтяной популяции**: пересечение множества
  рассольных ключей и множества нефтяных strict-ESP пробегов пусто.
* **T4 — не-нефтяные назначения исключены**: 0 пробегов с назначением из списка §3.2
  среди нефтяных.
* **T5 — 5 известных коллизий разведены**: VT_2704, VT_5607, YAW_5002, YAW_5601, YAW_5606
  — по каждому коду нефтяная и рассольная истории не смешаны (проверять по датам монтажа).
* **T6 — регресс числа пробегов/отказов по полю** не должен молча измениться на не-нефтяных
  стволах: залогировать, сколько строк выкинуто фильтром §3.2, с разбивкой по назначению.

## 5. Чего НЕ делать

* НЕ чинить это дедупом «Big против себя» — он спрячет VT_2704 по случайности (закрытые
  `рс`-пробеги перекроют открытый), но оставит 16 других фантомных рассольных пробегов и
  не тронет саму мисклассификацию.
* НЕ полагаться на `is_esp_strict` как на признак нефтяного ствола — он True на рассоле.
* НЕ решать вопрос «нефтяная или нет» по номеру скважины — только по суффиксу и назначению.

## 6. Отдельный, НЕ рассольный случай (не путать)

YA_601 — фантомный «живой» пробег с монтажа 2016 (возраст 3659 сут), НЕ рассольный: это
открытая строка Big, у которой в истории есть закрытый пробег, оканчивающийся 2017-09-02.
Это дефект «устаревшая открытая строка Big», а не идентичности. Лечится проверкой: живой
пробег не может стартовать раньше последнего ЗАКРЫТОГО пробега той же скважины. Стоит
добавить как отдельный тест T7, но механизм другой.

## 7. Для сверки (внешние источники правды по возрасту)

собой и противоречат приложенческому `сводпрогн3.xlsx` (у него «Факт ННО» — производная
CatBoost-величина, 97.7% значений кратны 1/7, это НЕ сутки наработки):
* **ПДК** (`D:/Projects/Pumps/data/pdk/Свод ПДК 2023-2026гг…xlsx`, лист `Свод`) — 2380
  закрытых ремонтов, 0 открытых; поздний монтаж в ПДК ⇒ наш живой пробег устарел;
* **техрежим** (текущий статус, поле «Время наработки (ННО)») — на дату asof подтверждает
  возраст 127 из 132 наших живых насосов старше 2 лет в пределах ~50 сут;
* **ДФ-04 / график ГТМ** (`…доп_ГТМ…xlsx`, лист `ДФ04_cводный`) — плановые вводы; дата
  ввода ГТМ до asof ⇒ повод проверить, не сменился ли насос.
