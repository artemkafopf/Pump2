## 2. Модель бейзлайна

`esp_forecast.fit_mc_model(pop)` — смесь Вейбулла k=2, «cal c0 k2»:

```
w1=0.0303  beta1=1.3147  eta1=0.500  beta2=1.3247  eta2=641.77
S(t) = w1*exp(-(t/eta1)^beta1) + (1-w1)*exp(-(t/eta2)^beta2)
```

* **Эстиманд — cause-specific**: событие = ОТКАЗ; ГТМ/ППР и работающие насосы в цензуру
  (`all_cause=False`, по умолчанию). `all_cause=True` даёт МРП для графика бригад —
  другой продукт, B50 ~240 против ~520.
* **Когорта Mc = монтажи 2024+** (`config.MC_INSTALL_COHORT_START`, `apply_mc_cohort`).
  Это фильтр по дате МОНТАЖА, НЕ левое усечение — усечение прячет, что свежие пробеги короче.
* **Часы**: `fit_mc_model` читает `mc["tte"]` из `esp_population.build` — это
  «Наработка (сут)» / Big `nno_days`. ⚠ Колонка `tte` СМЕШАННАЯ: закрытые пробеги на ННО,
  открытые проваливаются на календарный возраст (Mc 60 из 61 живых). Событий и цензур
  на РАЗНЫХ часах ⇒ выживаемость смещена ВВЕРХ. Новые чистые шкалы —
  `esp_population.add_time_scales` (`t_cal`, `t_nno`) + `esp_optime.add_op_scales`
  (`t_op`, `t_mix`, `t_mix_source`, `kexp_used`); подробности в
  `docs/notes/production_risk_time_scales_proposal.md`. **Миграция `fit_mc_model` на
  `t_cal`/`t_mix` НЕ сделана** — это открытая задача (§9.1), она двигает продовые числа.
* ⚠ `cal_c0_k2` стоит на границах (`b2_at_bound`, `eta1` на полу) ⇒ **`beta2`/`eta2`
  наружу как «износ» НЕ давать**, хотя направление опасности они и задают (§5).

## 3. Цепочка сборки

```
P.build(asof)                         # популяция пробегов
  → M.fit_mc_model(pop)               # модель cal c0 k2
  → M.live_fleet(pop, asof)           # 61 работающий насос
  → M.plan_entrants(...)              # ВНС + БАЗА между насосами, из плана ПП
  → M.forecast(model, live, entrants=…, months=18)   → (monthly, per_well)
  → M.allocate_events(monthly, per_well)             → {скв.: [месяцы отказов]}
  → repair_compat.build / write_excel                → лист «Repair forecast»
```

* **Вселенная скважин — ПЛАН, а не наши пробеги.** Парк растёт 67 → 82 за 18 мес за счёт
  **49 ВНС**; они дают **+23.2 отказа сверх 52.0 = 75.3**, треть прогноза. Знаменатель
  интенсивности ОБЯЗАН включать тот же набор: `active_fleet_by_month(codes=codes |
  set(entrants.code))`, где `codes` — ВСЯ популяция Mc, не `live_codes` (иначе история
  2024-10 падает 19 → 15).
* **«В работе»** = активные ДОБЫВАЮЩИЕ скважины плана (op_days>0 И (нефть>0 ИЛИ жидк>0)),
  2024-10 = **19**, не 36 пробегов.
* **Обновление (renewal)**: отказавший насос сразу меняется на новый с возраста 0
  (`forecast`, `nxt[0] = n_fail`), поэтому скважина может отказать за горизонт дважды.

## 4. ⚠ Ядро: risk_30d и ДОЛГ — две разные величины

Именно здесь ломались все прошлые обсуждения. Имена зафиксированы решением пользователя
2026-07-20 и переименованы в коде (`esp_forecast.allocate_events`):

| имя | что это | важное свойство |
|---|---|---|
| **`risk_30d`** | ПРИРОСТ за месяц: ожидание отказов насоса за этот месяц, прямо из `per_well` | ожидаемое **ЧИСЛО** событий, НЕ P(≥1 отказ) — из-за renewal. При 0.03-0.17 разница 1-9%, но она есть |
| **`debt`** | ДОЛГ: накопленная сумма `risk_30d` **с даты расчёта** | **у ВСЕХ насосов стартует с нуля**; прошлая наработка в долг не входит |

```python
debt = {code: 0.0 for code in exp.index}          # <- ноль у всех, на asof
for j, per in enumerate(months):
    risk_30d = exp[mcols[j]]
    for code in debt:
        debt[code] += float(risk_30d[code])       # накопление
    n_m = int(np.floor(E[j] + carry)); carry = E[j] + carry - n_m
    for code in sorted(debt, key=debt.get, reverse=True)[:n_m]:
        out[code].append(per); debt[code] -= 1.0  # выдал событие — вернул 1
```

* **СКОЛЬКО**: `n_m = floor(E_m + carry)`, остаток копится по парку. Флотская сумма точна
  (81 при ΣE = 81.4).
* **КТО**: максимум накопленного долга. Оба входа — выход `forecast()`, **второго счёта нет**
  (прежняя раскладка трекала возраст ТОЧКОЙ, а `forecast` ведёт РАСПРЕДЕЛЕНИЕ массы —
  две динамики из одной модели неизбежно расходились: 17 против 23.2).
* **Предел целочисленности — арифметика, не дефект**: за 18 мес старый насос ожидает 0.90
  отказа, ВНС 0.47; ни у кого не выходит 1, поэтому 75 целых событий на 107 скважин
  ложатся как «75 × 1». Поскважинно |выдано − ожидание| ≤ **0.59**, флотский итог точен.

## 5. Порядок отказов: измерено и объяснено

### 5.1 Факт
**Порядок «старые первыми».** Spearman(«Наработка факт», день первого отказа) =
**−0.992** на `Сводпрогноз_Mc.xlsx`; −0.999 при прямом прогоне `esp_forecast`.
Первыми MC_206 (763 сут), MR_1906 (721), MC_305 (712); последними — ВНС возраста 0 (день 518).
7 насосов не получают событий вовсе, их медианный возраст 35 сут.

### 5.2 ⚠ Порядок задаёт ФОРМА ОПАСНОСТИ, а не правило долга
Долг у всех стартует с нуля ⇒ решают только приросты внутри горизонта. Проверено прогоном
ОДНОГО И ТОГО ЖЕ кода на живом парке Mc (61 насос, θ выключена, менялась только кривая):

| базовая кривая | risk_30d(возраст 100) | risk_30d(возраст 700) | ρ(возраст,дата) | очередь |
|---|---|---|---|---|
| Mc base (k2, beta≈1.32) | 0.0348 | 0.0621 | **−0.999** | старые первыми |
| beta = 1.0 | 0.0561 | 0.0561 | −0.064 | **порядка нет** |
| beta = 0.735 (Vt nonsour) | 0.0534 | 0.0332 | **+0.998** | **молодые первыми** |
| beta = 1.8 | 0.0180 | 0.0755 | −0.998 | старые первыми |

Накопленный ДОЛГ за 5 мес по стратам (код-семантика, с даты расчёта):

| страта | возраст 30 | возраст 750 | вывод |
|---|---|---|---|
| Mc (cal c0 k2) | 0.165 | **0.325** | старые копят вдвое быстрее |
| Vt_sour_Pooled (beta 1.008) | 0.844 | 0.857 | разброс **1.6%** — порядка нет |
| Vt_nonsour_Pooled (beta 0.837) | **0.286** | 0.171 | инверсия: молодые копят больше |

### 5.3 Что из этого следует
1. Правило долга **переносимо**, вывод «старые первыми» — **нет**. Перед портированием на
   другую страту ОБЯЗАТЕЛЬНО проверить знак beta и померить ρ заново.
2. Общефлотский лист `Changeout` (18 месторождений) имеет ρ(возраст, p_fail_90d) = **+0.044**
   по всему парку — направления страт гасят друг друга (Mc +0.94, Ya_nonsour_slb −0.99,
   Vt_nonsour_brt −0.85). Читать его как «сначала самые старые» **неверно**.
3. Очередь — **ДЕФОЛТНЫЙ ПОРЯДОК, а не предсказание**: модель даёт по скважинам близкие
   вероятности, правило разворачивает их в очередь. Это свойство ПРАВИЛА, а не сила
   сигнала в данных.

## 7. Ловушки, на которых уже спотыкались

1. **Два продукта — два эстиманда.** График бригад = all-cause МРП; KPI/интенсивность =
   cause-specific. Сосуществуют, не смешивать. `Σt/N` — это СКОРОСТЬ, а не ЖИЗНЬ, и
   валидна только при постоянной опасности (ННО 969 против наблюдённых 191).
2. **Слой Ql — СЦЕНАРНЫЙ, не база.** `θ=(Ql/Ql_ref)^ln(1.253)`, применяется как
   `q_eff = 1-(1-q)^θ`. Перенормирован к mean=1 (иначе выпуклость Йенсена молча поднимает
   тотал ~3.3%); сдвинул 9 скважин из 117, тотал 81→80. **`c4_gate` ПРОВАЛЕН: выигрыш MAE
   −0.1% при пороге 5%.**
3. **`Вероятностный прогноз` = возраст + расстояние до подъёма = ПОЛНОЕ ННО**, всегда ≥
   «Наработка факт». Один раз выставили остаточный ресурс — получили «Факт ННО > прогноза».
4. **Лист «Repair forecast»: 0 = день ОТКАЗА, 1 = все остальные дни.** Одна строка на скважину.
5. **Не изобретать новую раскладку листа** — только через `repair_compat.write_excel`.
6. **Свод-популяция**: не дедуплицировать внутри Свода (пробеги в 2 днях друг от друга
   реальны); Big-only ЗАКРЫТЫЕ пробеги нести обязательно (у Ya это треть событий).
   Всегда сверять n_failures фита с `esp_models.csv`.

## 9. Открытые задачи

1. **Миграция часов.** `fit_mc_model` читает смешанную `tte`. Перевести на `t_cal` или
   `t_mix` (и парно — экспозицию: fit на одних часах + план в оп-сутках занижает на 9-15%).
   Двигает продовые числа ⇒ только с явного согласия пользователя.
2. **Кэкспл как ковариата Cox.** `kexp_used` теперь поколоночно с провенансом. ДВЕ ловушки:
   (а) `kexp` — НИЖНЯЯ граница там, где покрытие неполное (ненаблюдённые сутки считаются
   простоем) ⇒ ограничиться `t_mix_source == "measured"`; (б) обратная причинность —
   отказывающий насос глушат, поэтому низкий Кэкспл может быть СЛЕДСТВИЕМ. Ландмарк-дизайн
   Phase D (Кэкспл за 0-90 сут → отказы ПОСЛЕ 90) — единственная безутечковая форма.
   Первый порядок эффекта уже съеден выбором оп-часов (скорость на оп-сутки плоская по
   утилизации, CV 0.028 против 0.209 на календарь) ⇒ вопрос в ОСТАТОЧНОМ эффекте поверх `t_mix`.
3. **Метрика очереди.** Сейчас ранжирование = долг (Mc) / `p_fail_90d` (общефлотский лист).
   Альтернатива — `exp_value_at_risk_90d_t` = p90 × нефть: она разрывает ничью на стратах с
   beta≈1, где возраст не даёт порядка вовсе.
4. **Пер-скважинный прогноз** — эмпирико-байесовская frailty на собственной истории
   скважины, НЕ CatBoost (проверено: censoring-blind, тянет из гистограммы).
