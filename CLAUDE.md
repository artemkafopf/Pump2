## Critical rules (enforced every session)

### 1. All paths come from `analysis.paths`

```python
from analysis.paths import results_dir, resolve_v03_all_path, resolve_telemetry_db_path
```

Never hardcode `D:\Projects\...` or `analysis_outputs/` in new code.
`analysis.input_paths` and `analysis.sqlite_paths` are legacy shims — do not use in new code.

### 2. All results go through `results_dir()`

```python
out = results_dir("my_analysis_slug")   # creates results/<slug>/YYYY-MM-DD/
(out / "tables" / "summary.csv").write_text(...)
(out / "figures" / "plot.png")  # save matplotlib figure here
```

Slug format: `<workflow>_<step>_<variant>` — e.g. `vt_failure_phase4_weibull`.

### 3. New reusable logic → `backend/analysis/`

Scripts in `scripts/` are thin CLI wrappers.  
Heavy logic (models, estimators, data loaders) lives in `backend/analysis/`.
See the project map above for which sub-package takes what.

### 4. sys.path bootstrap (scripts and streamlit apps)

```python
import sys
from pathlib import Path
REPO_ROOT = Path(__file__).resolve().parents[N]
sys.path.insert(0, str(REPO_ROOT / "backend"))
```

### 5. Мирнинский (Mc/Mr) = **installations 2024+ only**

Any statistic, fit, calibration or table that covers Мирнинский must be built from runs
**installed on/after 2024-01-01**:

```python
from analysis.workflows.production_risk import config as C
mc = pop[(pop["field"] == "Mc") & (pop["install"] >= C.MC_INSTALL_COHORT_START)]
```

* This is a **cohort filter on the install date** — not left truncation of exposure.
  Left-truncating (`add_entry_age`) keeps pre-2024 runs' later exposure and **hides that
  recent runs are shorter**; it was tried and is wrong.
* Pre-2023 Mc is the anomaly, not 2024+: **2 failures vs 11.8 expected on 21 runs** —
  luck or incomplete early records.
* Applies to `esp_population` selections, survival/hazard fits, failure-rate calibration
  and anything reported per-УН for Мирнинский. Other fields use all history.

### 6. Свод собирается ЗДЕСЬ — `backend/analysis/ingest/`

Регистр ЭЦН больше не приезжает готовым из соседнего репозитория: он собирается из сырых
выгрузок в этом же дереве, поэтому обработка входа и расчёт модели не могут разойтись.

```bash
python scripts/ingest/build_telemetry_db.py     # телеметрия  → data/sqlite/
python scripts/ingest/build_frac_db.py          # реестр ГРП  → data/sqlite/frac.sqlite
python scripts/ingest/build_svod.py             # Свод + диф  → results/svod_build_full/
```

* ⚠⚠ **Сборка идёт НА ПОСЛЕДНЮЮ ДАТУ ПДК.** Отказы приходят только из ПДК, живые пуски —
  из паспорта оборудования, который обновляется отдельно. Всё правее последней записи ПДК —
  экспозиция, в которой событие записать нечем, и она смещает выживаемость вверх ровно в
  ранней полосе. Отсюда три правила, все в `_apply_observation_horizon`:
  пуск, смонтированный **после** горизонта, выбрасывается (чистое разбавление); живой пуск
  цензурируется **горизонтом, а не сегодняшним днём**; пуск, закрывшийся **за** горизонтом,
  не теряется, а остаётся цензурированным на горизонте. Переопределяется `--as-of`, когда
  последний месяц выгрузки заведомо неполон (сборщик об этом предупреждает сам).
* Сборка пишет в `results/`, **живой вход `data/inputs/Отказы свод с анализом.xlsx` не
  трогает**. Промоут — отдельное осознанное действие после просмотра дифа.
* Разметка причин (`группа_причины`, `спорная_зона`, `узел_категория`) считается в
  `ingest/svod/causes.py` и приезжает в Своде уже заполненной. Классификатор узла живёт
  ТОЛЬКО там; `vt_failure/data.py` его импортирует, копию не держит.
* ⚠⚠ `Флаг отказа == 0` ≠ «работает»: под нулём лежат и подъёмы по ГТМ/ППР. Работающий
  пуск определяется **пустой датой окончания** — колонка `Работает`.
* ⚠ Стыковка чего угодно с регистром — только по `(скважина, дата монтажа)`.
